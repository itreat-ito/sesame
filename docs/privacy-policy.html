プライバシーポリシー

拡張機能: Sesame!
施行日: 2026年4月13日

本プライバシーポリシーは、ブラウザ拡張機能「Sesame!」（以下「本拡張機能」）が、利用時にどのように情報を取り扱うかを説明するものです。 本拡張機能は、お客様が登録したドメインまたは URL パターンに対し、HTTP Basic 認証（BASIC 認証）の資格情報をブラウザに代わって提示することで、繰り返しの手入力を減らすために提供されています。

概要

  • お客様の個人情報を販売しません。
  • 本拡張機能内に広告やアクセス解析用のトラッカーを組み込んでいません。
  • 資格情報・設定・ログ等のデータは、開発者のサーバーへ送信する設計にはなっていません。主に chrome.storage.local を用いてお客様のブラウザ内（端末内）に保存されます。
  • 本拡張機能は chrome.storage.sync を用いた Chrome プロファイル間の同期には対応していません。

本拡張機能が取り扱う情報

本拡張機能は、機能の提供に必要な範囲でのみデータを処理します。

  • ネットワーク上の認証チャレンジに関する情報: サイトが HTTP Basic 認証を要求した際、リクエストの URL 等を参照して、お客様が登録したパターンと照合し、資格情報を提示できるかどうかを判断します。また、任意の認証ログ（成功・失敗、時刻、対象 URL、ユーザー名、パスワードを含む場合があります）を端末内に記録できます。これらの処理はブラウザの拡張機能 API 上で行われます。
  • アクティブなタブの情報（拡張機能の UI 利用時）: ツールバーのポップアップを開いたとき、現在のタブの URL（ホスト名の取得を含む）を読み取り、入力欄への事前入力や、登録済みかどうかの表示に利用します。
  • お客様が登録・設定した項目: ドメインまたは URL パターン、ユーザー名、パスワード（パスワードは AES-GCM で暗号化したうえで保存）、動的パスワード用テンプレート、エントリの有効／無効、表示順、直近の認証成功時刻などです。
  • 暗号化キー: パスワードの暗号化に用いる鍵は、端末上で生成され chrome.storage.local に保存されます。

ウェブサイトへの資格情報の送信について

お客様が登録したサイトが BASIC 認証を要求した場合、ブラウザの通常の動作として、そのサイトへの HTTPS／HTTP リクエストにユーザー名とパスワードが含まれることがあります。 これは本拡張機能の目的である「登録済みサイトへの自動入力」に必要な動作であり、開発者が別途その内容を収集するものではありません。

ネットワーク通信と第三者

本拡張機能は、資格情報や利用状況を開発者のサーバーに送信する機能を備えていません。 お客様が本拡張機能の画面から外部ウェブサイト（例: ストアのポリシーや Google のポリシー）のリンクを開いた場合は、それらのサイトのポリシーが適用されます。

Chrome のストレージ

データは原則として chrome.storage.local に保存され、お客様の端末に留まります。 Chrome の設定から拡張機能のデータを消去する、本拡張機能をアンインストールする、オプションで編集するなど、お客様が削除するまで保持されます。

権限とその理由

  • webRequest — HTTP Basic 認証が要求されたリクエストを検知し、完了・エラーと照合してログを残すため。
  • webRequestAuthProvider — Manifest V3 において、認証プロバイダーとしてユーザー名・パスワードを提示するため。
  • storage — 資格情報、暗号化キー、認証ログ、UI の状態などの保存・読み込みのため。
  • activeTab — ユーザーが拡張機能を操作したときに、現在のタブに関する必要な情報にアクセスするため。
  • tabs — ポップアップでアクティブなタブの URL を取得するため。
  • ホスト権限（<all_urls>） — お客様が任意のオリジンを登録し得るため、登録済みパターンに合致するリクエストで BASIC 認証に応答するリスナーを必要な範囲で登録するため。ページの内容を読み取り・改変するコンテンツスクリプトは使用していません。

データの保存期間

設定およびログは、Chrome で拡張機能のデータを消去する、本拡張機能をアンインストールする、オプションまたはログ画面で削除するなど、お客様が削除するまで保持されます。 認証ログは件数上限に達した場合、古いものから順に破棄される場合があります。

お子様について

本拡張機能はお子様を対象としたものではなく、故意にお子様から個人情報を収集することはありません。

本ポリシーの変更

本拡張機能の動作や要件の変更に伴い、本プライバシーポリシーを更新することがあります。 更新時には冒頭の施行日を改訂します。

お問い合わせ

本拡張機能に関するプライバシーに関するお問い合わせは、Chrome ウェブストアの当該拡張機能ページに記載の開発者連絡先をご利用ください。

Privacy Policy

Extension: Sesame!
Effective date: April 13, 2026

This Privacy Policy describes how the Sesame! browser extension (“Extension”) handles information when you use it. The Extension helps you avoid repeatedly typing HTTP Basic Authentication credentials by supplying credentials you have saved for specific domains or URL patterns.

Summary

  • We do not sell your personal information.
  • We do not run advertising or analytics trackers inside the Extension.
  • Credentials, settings, and logs are not designed to be transmitted to the developer’s servers. They are stored primarily in chrome.storage.local on your device.
  • The Extension does not use chrome.storage.sync to sync data across Chrome profiles.

Information the Extension processes

The Extension processes data only as needed to provide its features:

  • Authentication-related network information: When a site requests HTTP Basic Authentication, the Extension inspects the request URL (and related request metadata) to match your saved patterns and decide whether to supply credentials. It may also record optional authentication logs (success or failure, time, URL, username, and—depending on how you use the log feature—password) locally on your device. Processing occurs through the browser’s extension APIs.
  • Active tab information (Extension UI): When you open the toolbar popup, the Extension reads the active tab’s URL (including the hostname) to pre-fill fields and to show whether a matching entry exists.
  • Data you configure: Domain or URL patterns, usernames, passwords (passwords are encrypted with AES-GCM before storage), optional dynamic password templates, enabled/disabled state per entry, display order, and optional timestamps such as last successful authentication.
  • Encryption key: A key generated on your device for password encryption is stored in chrome.storage.local.

Sending credentials to websites

When a site you registered requests HTTP Basic Authentication, the browser may include those credentials in HTTPS/HTTP requests to that site as part of normal browser behavior. That is required for the Extension’s core purpose (automatic credential submission). The developer does not collect those credentials on a separate server.

Network requests and third parties

The Extension does not include functionality to send your credentials or usage data to the developer’s servers. If you open external links from the Extension (for example, to a policy page or the Google Privacy Policy), those sites apply their own policies.

Chrome storage

Data is stored primarily in chrome.storage.local and remains on your device until you remove it (for example by clearing extension data in Chrome, uninstalling the Extension, or deleting entries through the options or log UI).

Permissions (why they exist)

  • webRequest — Detect HTTP Basic Authentication challenges and correlate requests with completion or error events for optional logging.
  • webRequestAuthProvider — Act as an authentication provider and supply username/password for HTTP Basic Authentication under Manifest V3.
  • storage — Save and load credentials, encryption keys, authentication logs, and UI-related state.
  • activeTab — Access the current tab when you interact with the Extension in a user-initiated context.
  • tabs — Read the active tab’s URL when the popup opens.
  • Host access (<all_urls>) — You may register any origin; the background listener must handle authentication-related events for requests that match your saved patterns. The Extension does not use content scripts to read or modify page content on websites.

Data retention

Your settings and logs remain until you delete them or uninstall the Extension. Authentication logs may be trimmed when a maximum number of entries is reached, with older entries removed first.

Children

The Extension is not directed at children, and we do not knowingly collect personal information from children.

Changes to this policy

We may update this Privacy Policy when the Extension’s behavior or requirements change. The effective date at the top will be revised when updates are published.

Contact

For privacy questions about this Extension, please use the developer contact information shown on this Extension’s Chrome Web Store listing page.
